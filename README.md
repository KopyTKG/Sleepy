# sleepy

`sleepy` converts an **OpenAPI 3** specification (JSON or YAML) into an
**Insomnia v4 export** JSON document (`_type: "export"`,
`__export_format: 4`).

It ships as two apps sharing one engine:

- **`sleepy`** — a single-binary command line tool.
- **`sleepy-GUI`** — a desktop app ([Uno Platform](https://platform.uno/),
  Linux and Windows) with a drop-here zone and dropdowns for the output
  options.

It works with any OpenAPI 3 document and emits a generic bearer-auth collection
driven by environment variables (`baseUrl`, `bearer`).

It also handles **multi-module APIs**: when a URL points at a Swagger UI that
serves several definitions (the "Select a definition" dropdown — Swashbuckle,
springdoc grouped APIs, springfox), sleepy discovers every module, fetches them
all, and merges them into one collection with a folder per module.

## What it produces

The export contains:

- A `workspace` resource (named after the spec's `info.title`).
- One `environment` resource named **"Base Environment"** whose `data` is
  `{ "baseUrl": "<origin>", "bearer": "" }`. When the spec is fetched from a URL
  (see below), `baseUrl` is prefilled with that URL's origin
  (e.g. `https://api.example.com`); otherwise it is left empty (`""`).
- One `request_group` (folder) per OpenAPI **tag** (the operation's first tag,
  or `default`), sorted alphabetically. With several modules, tag folders are
  nested inside a folder per module (or flattened to `"<Module> / <Tag>"` with
  `--flat`).
- One `request` per operation (`get`/`post`/`put`/`delete`/`patch`), each with:
  - a stable `_id` derived from `operationId` (or `<method>_<path>`), slugified
    and prefixed `req_`;
  - `name` = `"<METHOD> <path>"`, uppercase `method`;
  - `url` = `"{{ _.baseUrl }}<path>"`;
  - `parentId` = the tag folder's id;
  - a `Content-Type: application/json` header when the operation has a
    `requestBody`;
  - query `parameters` (from `parameters` where `in == "query"`);
  - bearer `authentication`: `{ "type": "bearer", "token": "{{ _.bearer }}" }`;
  - a `body` with a generated example JSON object when the request body has a
    `application/json` schema.

With a single module the output is exactly what it always was — the module
folder level and the module-prefixed ids only appear once there are two or more.

Output is deterministic: object keys are written in ordinal order and paths are
processed sorted, so the same spec always yields byte-identical output.

### Schema → example generation

Request-body examples are generated by recursively walking the JSON schema:

- `$ref` is resolved against the root document (`#/...`), with cycle guarding
  and a depth cap (~6).
- `allOf` merges all subschema objects; `oneOf`/`anyOf` use the first entry.
- `enum` uses its first value; an explicit `example` is used as-is.
- `string` → `""`; `format: date-time` → an ISO timestamp placeholder,
  `format: date` → an ISO date, `format: uuid` → the all-zero UUID.
- `integer`/`number` → `0`, `boolean` → `false`.
- `array` → `[ example(items) ]`.
- `object` (or unspecified) → an object of `property → example(property)`.

> Note: date/date-time placeholders and `__export_date` are fixed strings
> (`2020-01-01T00:00:00Z` / `2020-01-01`) rather than the current time, to keep
> output reproducible.

## Multi-module APIs

Point sleepy at the Swagger UI URL — the same one you have open in the browser —
and it pulls every definition from the dropdown:

```sh
# The whole API: one folder per module, tag subfolders inside
sleepy https://api.example.com:12000/swagger/index.html -o insomnia.json

# See what would be pulled, without converting
sleepy https://api.example.com:12000/swagger/index.html --list

# Only some modules (repeatable, case-insensitive)
sleepy https://api.example.com:12000 --module Admin --module Workflow -o insomnia.json

# Several specs listed by hand — each becomes a module
sleepy https://a.example.com/openapi.json ./billing.json -o insomnia.json
```

To find the module list, sleepy accepts (and probes for) any of:

| Source | Shape |
| --- | --- |
| `swagger-ui-init.js` | Swashbuckle: `"urls":[{"url":...,"name":...}]` embedded in the script |
| `/v3/api-docs/swagger-config` | springdoc: `{"urls":[{"url":...,"name":...}]}` |
| `/swagger-resources` | springfox: `[{"name":...,"location":...}]` |
| a manifest you write | the same `{"urls":[{"name":...,"url":...}]}` JSON, with URLs or paths relative to the manifest |

Given a URL that is not itself a document, sleepy probes `swagger-ui-init.js`,
`swagger/v1/swagger.json`, `v3/api-docs/swagger-config`, `swagger-config`, and
`swagger-resources`, relative to both the URL's directory and the site root. So
`https://host:12000`, `https://host:12000/swagger/index.html`, and
`https://host:12000/swagger/index.html?urls.primaryName=Admin` all work.

Module names come from the dropdown (falling back to `info.title`), and resource
ids are prefixed with the module slug, so two modules exposing the same
`operationId` do not collide.

### baseUrl with several modules

- All modules on one origin → a single `baseUrl` variable, prefilled with it.
- Modules on different origins → one variable per module
  (`baseUrl_<module>`), each prefilled from that module's spec URL, and each
  request uses its own.
- `--base-url <url>` forces a single shared `baseUrl` for everything.

Every request still authenticates with `{{ _.bearer }}`, so filling in `bearer`
once covers all modules.

### Specs behind auth or a self-signed certificate

```sh
sleepy https://api.example.com/swagger/index.html \
  -H "Authorization: Bearer $TOKEN" -H "X-Tenant: acme" --insecure -o insomnia.json
```

`-H` / `--header` (repeatable) and `-k` / `--insecure` apply to fetching the
spec documents only; they are not written into the export.

## sleepy-GUI (desktop app)

The window is two panes: the controls on the left, a live preview of the export
on the right, and a status line along the bottom.

Drop an `openapi.json` / `swagger.yaml` anywhere on the window — or paste a path
or a Swagger UI URL and press Enter — and sleepy loads every module it finds.
Then:

- tick the **modules** to include (shown when the input serves more than one);
- pick the **folder layout**: module folders with tag subfolders, flat
  `"Module / Tag"` folders, or module folders only;
- set the **workspace name**, the **base URL**, and optionally a **bearer
  token** that is written straight into the environment;
- open **Fetch options** (top right of the spec source section) to send a
  request header (e.g. `Authorization: Bearer …`) or to ignore TLS certificate
  errors while fetching;
- watch the **preview** pane and its request count update as you change the
  options, then **Save export…** or **Copy JSON**.

Drag and drop uses the platform's own file drop support; where the desktop does
not provide it, the path/URL box and the **Browse…** button do the same job.

### Languages

The app ships English and Czech. It follows the system language by default; the
picker in the bottom-right corner pins it to one language and remembers the
choice. Counted phrases use proper plural forms, including the Czech
one/few/many split (`1 požadavek`, `3 požadavky`, `8 požadavků`).

Strings live in `src/Sleepy.Gui/Strings/<language>/Resources.resw`: XAML text is
keyed by `x:Uid`, and the messages the view model builds go through
`Services/Localizer.cs`. Adding a language means copying a `Resources.resw`
folder, translating it, and adding the tag to `Localizer.SupportedLanguages`
plus an entry in the picker.

### Linux: X11, Wayland, or a bare console

The app renders with Skia through Uno's **X11** host, or straight on the
**framebuffer/DRM** with no session at all. Uno has no native Wayland backend
yet, so on a Wayland session the X11 host runs through **XWayland** — which
every common compositor ships, so it works out of the box.

The Linux build therefore carries one binary and three launchers:

| Launcher | Session |
| --- | --- |
| `sleepy-gui-x11` | an X11 session |
| `sleepy-gui-wayland` | a Wayland session, via XWayland (fails clearly if XWayland is off) |
| `sleepy-gui-console` | no session at all — framebuffer/DRM from a TTY |
| `sleepy-gui` | picks a host automatically |

The host can also be forced directly with `--display x11`,
`--display framebuffer`, or the `SLEEPY_GUI_DISPLAY` environment variable.

`install.sh` in the same folder installs the app to `~/.local/share/sleepy-gui`,
puts the launchers on `PATH`, and registers both desktop entries plus the icon
(`PREFIX=…` overrides the location).

The app icon comes from `icon.png` in the repository root — replace that file
and rebuild to change every icon size, the Windows `.ico`, and the splash
screen (`src/Sleepy.Gui/Assets/Splash/splash.png` keeps a copy of the same
artwork, because Resizetizer will not share one file between the two).

### Run it

```sh
# From source
dotnet run --project src/Sleepy.Gui -f net10.0-desktop

# Self-contained build, Linux
dotnet publish src/Sleepy.Gui/Sleepy.Gui.csproj -c Release -f net10.0-desktop \
  -r linux-x64 --self-contained -o dist/gui
./dist/gui/sleepy-gui-wayland    # or -x11, -console, or ./dist/gui/sleepy-gui

# Self-contained build, Windows (cross-compiles from Linux too)
dotnet publish src/Sleepy.Gui/Sleepy.Gui.csproj -c Release -f net10.0-desktop \
  -r win-x64 --self-contained -o dist/gui-win
```

On Windows you can also build the WinAppSDK head
(`-f net10.0-windows10.0.26100`), which is enabled automatically when the build
runs on Windows and needs the Windows SDK.

## Build

The toolchain is pinned with [mise](https://mise.jdx.dev/) and every task runs
through [just](https://just.systems/):

```sh
mise install     # .NET 10 SDK + just, as pinned in mise.toml
just             # list every recipe
```

The Uno SDK version is pinned separately in `global.json`.

| Recipe | What it does |
| --- | --- |
| `just build` | build the whole solution |
| `just build-cli` | build only the CLI and the engine (fast loop) |
| `just test` | run the test suite |
| `just coverage` | tests plus a Cobertura report under `dist/coverage` |
| `just lint` / `just fmt` | check / apply formatting |
| `just run openapi.json -o out.json` | run the CLI |
| `just gui` | run the desktop app |
| `just publish-cli` | Native AOT CLI binary |
| `just publish-gui-linux` | self-contained Linux app with its launchers |
| `just publish-gui-windows` | self-contained Windows app (cross-publishes from Linux) |
| `just package` | all of the above, archived exactly as the release job uploads them |
| `just set-version 0.6.0` / `just tag 0.6.0` | bump the version everywhere / tag a release |
| `just ci` | lint + build + test + package, what CI runs |
| `just clean` | drop `bin/`, `obj/`, and `dist/` |

Without mise or just, the plain SDK commands still work:

```sh
dotnet build
dotnet test
dotnet run --project src/Sleepy.Cli -- openapi.json
dotnet publish src/Sleepy.Cli/Sleepy.Cli.csproj -c Release -r linux-x64 -o dist/cli
```

The CLI release build uses **Native AOT**, which links with `clang` and needs
the zlib headers (`apt-get install clang zlib1g-dev` on Debian/Ubuntu). Swap
`-r linux-x64` for `win-x64`, `osx-arm64`, etc. — Native AOT must be built on
the target OS.

## Tests

`tests/Sleepy.Core.Tests` covers the engine: slugs, the deterministic JSON
writer, JSON/YAML parsing, schema example generation (`$ref`, cycles, `allOf`,
`oneOf`, formats, the depth cap), the Insomnia resource shapes for every folder
layout, and module discovery against a loopback Swagger UI (Swashbuckle,
springdoc, springfox, and manifests).

A golden test converts `tests/Sleepy.Core.Tests/Fixtures/openapi.json` and
compares it byte for byte with the recorded export, and asserts the YAML twin
produces the same thing. When the output changes on purpose, re-record it with
`just bless` and review the diff.

## Usage

```
sleepy <spec|url|-> [<spec|url> ...] [options]
```

| Option | Meaning |
| --- | --- |
| `-o`, `--output <file>` | write the export to a file instead of stdout |
| `--base-url <url>` | override the environment's `baseUrl` for every module |
| `--name <name>` | workspace name (default: the spec title, or the host for multi-module) |
| `--module <name>` | only include this module; repeatable, case-insensitive |
| `--flat` | one folder level named `"<Module> / <Tag>"` instead of nesting |
| `--no-tags` | a folder per module only, without tag subfolders |
| `--bearer <token>` | prefill the environment's `bearer` variable |
| `-H`, `--header <h>` | extra request header when fetching, e.g. `"Authorization: Bearer x"`; repeatable |
| `-k`, `--insecure` | do not verify TLS certificates when fetching |
| `--list` | print the discovered modules and exit |
| `-h`, `--help` / `-v`, `--version` | help / version |

- Each input may be a **file path**, an **http(s) URL**, or `-` for **stdin**,
  and several inputs may be given at once. JSON and YAML are both accepted;
  the syntax is detected from the content (and from the file extension).
- When the input is a URL, sleepy fetches over HTTP and prefills the
  environment's `baseUrl` with the URL's **origin** (scheme + host + optional
  port), so requests target the live API out of the box.
- If `-o` is omitted, the export is written to **stdout**; progress notes go to
  stderr, so piping stays clean.
- On bad usage the process exits with 2; on a failed fetch, read, or parse it
  prints a message to stderr and exits with 1.

### Examples

```sh
# From a file to stdout
sleepy openapi.json

# From a file to a file
sleepy openapi.json -o insomnia.json

# Fetch a live spec by URL — baseUrl is set to https://api.example.com
sleepy https://api.example.com/openapi.json -o insomnia.json

# Fetch by URL but point requests at a different host
sleepy https://docs.example.com/openapi.json --base-url https://api.example.com

# From a live endpoint via stdin (pipe it yourself)
curl -s https://api.example.com/openapi.json \
  | sleepy - --base-url https://api.example.com -o insomnia.json
```

Then import the resulting `insomnia.json` in Insomnia via
*Import → From File*. The `baseUrl` is already filled in when you passed a URL;
otherwise fill in `baseUrl` (and `bearer`) on the "Base Environment".

## Scope

`sleepy` targets **OpenAPI 3** documents in JSON or YAML. Trailing commas and
comments in JSON input are tolerated.

Only local `$ref`s (`#/...`) are resolved — remote and file references are not
followed. OpenAPI `servers` entries are ignored; the request URL is
`{{ _.baseUrl }}` plus the raw path from the spec.
